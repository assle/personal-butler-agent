# 群聊总结——实施方案

**目标：** 当用户在企业微信群聊中通过“总结一下群消息”@提及机器人时，机器人会检索最近的群消息，通过LLM生成结构化摘要，并在群聊中回复。

**前提：**企业微信管理控制台→应用设置→接收消息→**启用“群聊消息”**。如果没有这个，自建应用只能接收@mention消息，无法被动收集群聊历史。

**架构：**

```
Group Chat Messages (all) → WeChat Work → POST /api/wechat/callback
                                                  ↓
                                         Parse ChatId / ChatType
                                                  ↓
                                    ┌─────────────┴──────────────┐
                                    ↓                            ↓
                           chat_type == "group"          chat_type == "single"
                           ALWAYS save to DB             (existing flow)
                                    ↓
                          ┌─────────┴─────────┐
                          ↓                   ↓
                   @bot + "总结"       Not a trigger
                   keyword?           Return empty 200
                          ↓              (no reply)
                   Fetch last N msgs
                   from DB for ChatId
                          ↓
                   LLM summarization
                          ↓
                   Encrypted reply
                   → Group Chat
```

## 任务 1：更新消息解析以检测群聊上下文

**文件：** `src/wechat/messages.py`、`tests/test_wechat_messages.py`

将 `chat_id` 和 `chat_type` 字段添加到 `InnerMessage` 数据类。更新了 `parse_inner_xml()` 以从内部 XML 中提取 `ChatId` 和 `ChatType`。

## 任务2：创建群消息存储模型

**文件：** `src/models/group_message.py`（新）、`tests/test_group_message_model.py`（新）

创建了 `GroupMessage` ORM 模型，其中字段：`id`、`chat_id`（索引）、`user_id`、`content`（文本）、`create_time`（整数）、`stored_at`（日期时间）。三个类方法：
- `save()` — 保留一条消息记录
- `get_recent()` — 按时间顺序获取最后 N 条消息，按时间顺序返回
- `cleanup()` — 只保留每组最近的 N 条消息

## 任务3：在回调中被动保存群消息

**文件：** `src/wechat/router.py`、`tests/test_wechat_router.py`

所有群聊消息（chat_type =“group”）都保存到数据库中。非触发消息返回空200（静默收集）。触发关键词检测：包含“总结”、“摘要”、“概括”、“汇总”的消息。

## 任务4：实现群聊汇总节点

**文件：** `src/agents/summary/state.py`、`src/agents/summary/nodes.py`、`src/agents/summary/graph.py`、`tests/test_summary.py`

在 `SummaryState` 中添加了 `chat_id` 和 `chat_type`。添加了 `summarize_group_messages()` 节点和 `GROUP_SUMMARY_PROMPT`。添加了基于 `chat_type` 的 START 条件路由：“group”→ `summarize_group_messages`，else → `generate_summary`。更新了 `handle()` 以接受可选的 `extra_state` 参数。在`src/main.py`中注册了`summarize_group`意图。

## 任务5：端到端集成和手动验证

**调试端点：** 使用 `chat_type` 和 `chat_id` 字段更新了 `DebugMessageRequest`。更新了调试路由器以保存组消息、处理触发检测并路由到 `summarize_group`。

**E2E测试：** `tests/test_e2e_group_summary.py`中的4个测试：全流程（收集→触发→汇总）、组消息隔离、触发关键字变体、空组处理。

**手动步骤：**
1. 企业微信管理员→开启“群聊消息”
2. 添加机器人来测试群聊
3. 部署并发送正常消息以构建历史记录
4. @bot 带有“总结一下群消息” → 验证结构化摘要回复

## 关键设计决策

1. **被动收集+触发式回复：** 所有群消息均静默保存。只有@mention+总结关键字才会触发回复。
2. **每组消息上限为 200：** 防止数据库无限增长。
3. **重用现有的 SummaryAgent：** 通过条件路由添加的 `summarize_group` 分支。
4. **通过关键字匹配进行@提及检测：** 在足以进行检测的内容中触发关键字。

## 后续：智能机器人回调集成（2026-05-31完成）

部署自建应用回调后，实际测试发现**智能机器人（智能机器人）API模式**使用与自建应用根本不同的协议。

### 机器人回调修复

- [x] **修复 1：添加机器人特定配置** - `src/config.py` 和 `.env.example` 中的 `WECHAT_ROBOT_TOKEN` + `WECHAT_ROBOT_ENCODING_AES_KEY`

- [x] **修复 2：创建机器人回调路由器** — `src/wechat/robot_router.py` 和 `GET/POST /api/wechat/robot/callback`

- [x] **修复 3：解析智能机器人 JSON 格式** — 机器人发送不同的 JSON 模式：`from.userid`（嵌套）、`text.content`（嵌套）、`chatid`、`chattype`、`response_url` — 与自建应用的平面 `from_user_name`/`content`/`chat_id` 字段完全不同。

- [x] **修复 4：通过 response_url 进行主动回复** — 机器人不支持被动加密 XML 回复。相反，`_post_reply()` 将回调消息中的 JSON POST 到 `response_url`。这也避免了被动回复的5秒超时限制。

- [x] **修复 5：使用 markdown msgtype** — 机器人的 `response_url` 仅支持 `markdown` 和 `template_card` 消息类型。使用 `text` 返回错误代码 40008（“无效消息类型”）。将 `_post_reply()` 有效负载从 `text` 更改为 `markdown`。

- [x] **修复 6：加密中的 receiveid 为空** — 机器人的 URL 验证和消息解密使用 `receiveid=""`（空字符串），而不是 CorpID。 GET echostr 解密调用 `decrypt(key, echostr, "")`。

### 机器人特定的架构决策

| 方面 | 自建应用 | 智能机器人 |
|--------|---------------|-------------------|
| 路线 | `/api/wechat/callback` | `/api/wechat/robot/callback` |
| 配置 | `WECHAT_CORP_ID` + `WECHAT_TOKEN` + `WECHAT_ENCODING_AES_KEY` | `WECHAT_ROBOT_TOKEN` + `WECHAT_ROBOT_ENCODING_AES_KEY` |
| 消息格式 | XML 或平面 JSON（`FromUserName`、`Content`、`ChatId`） | 嵌套 JSON（`from.userid`、`text.content`、`chatid`、`response_url`） |
| 回复机制 | HTTP 响应中的被动加密 XML | 主动 POST JSON 到 `response_url` |
| 回复消息类型 | `text`（通过 XML） | 仅限 `markdown`、`template_card` |
| 加密接收ID | 公司ID | `""`（空字符串） |
| 5秒超时 | 是（被动回复） | 否（主动回复） |
| 记录于 | `src/wechat/router.py` | `src/wechat/router.py`+ADR-008 |

### 确认

- `tests/test_wechat_robot_router.py` 中的 14 个测试涵盖：GET URL 验证（receiveid=""）、POST 机器人 JSON 解析、通过 response_url 进行组触发汇总、非触发静默收集、与自建应用的 CorpID 隔离。
- 总共 82 项测试通过。
- 生产验证：@bot +“总结”在群聊中成功返回 markdown 格式的摘要。
