# 活跃上下文

## 当前状态

MVP 已完成并迁移到 LangChain + LangGraph。应用暴露 `POST /api/debug/message`、`POST /api/wechat/callback`（自建应用）和 `POST /api/wechat/robot/callback`（智能机器人），消息经过规则优先的意图路由器，分发到四个 LangGraph StateGraph 代理之一，并在 SQLite 中持久化健身/群聊消息/用户偏好状态。

当前实现基线：
- FastAPI 应用入口: `src.main:app`
- 调试路由: `src/router/debug.py` — 支持 chat_type/chat_id 进行群聊模拟
- 企业微信自建应用回调: `src/wechat/router.py` — GET URL 验证 + POST 消息接收，AES-256-CBC 加解密，CorpID 校验，被动加密 XML 回复
- 企业微信智能机器人回调: `src/wechat/robot_router.py` — GET URL 验证（receiveid=""）+ POST 智能机器人专用 JSON 解析，通过 `response_url` 主动推送回复
- 意图路由: `src/intent/rules.py` 和 `src/intent/router.py`
- 代理: `FitnessAgent`、`SummaryAgent`（文本 + 群聊）、`MealAgent`、`QAAgent`
- 代理注册表: `src/agents/registry.py` — 7 个 intent→agent 映射
- LLM: `langchain_openai.ChatOpenAI` 指向 DeepSeek
- 持久化: `training_records`、`user_preferences`、`group_messages`
- 多轮记忆: LangGraph `MemorySaver` checkpointing（进程内内存，按 user_id 线程隔离）
- 验证基线: 82 个测试通过，`DEEPSEEK_API_KEY=test uv run pytest -q`
- 配置: `WECHAT_ROBOT_TOKEN` + `WECHAT_ROBOT_ENCODING_AES_KEY` 用于智能机器人回调（与自建应用的 `WECHAT_CORP_ID` + `WECHAT_TOKEN` + `WECHAT_ENCODING_AES_KEY` 并存）

## 已实现

- 调试 API 请求/响应模式（带 chat_type/chat_id 用于群聊模拟）。
- 企业微信自建应用回调（AES-256-CBC 加解密、XML 解析、被动加密 XML 回复）。
- 企业微信智能机器人 API 回调（receiveid="" 解密、智能机器人 JSON 消息解析、通过 `response_url` 主动推送回复）。
- 已知意图关键字的规则优先分类。
- 通过 LangChain ChatOpenAI 进行 DeepSeek/OpenAI 兼容的 LLM 回退分类。
- 训练记录提取和持久化（FitnessAgent StateGraph）。
- 基于最近历史记录的训练计划生成（FitnessAgent StateGraph）。
- 结构化聊天总结 — 私聊文本和群聊历史（SummaryAgent StateGraph 条件路由）。
- 群聊消息被动收集：所有群聊消息保存到数据库，触发关键字（"总结"/"摘要"/"概括"/"汇总"）启动总结。
- 偏好感知的饮食规划和问答（MealAgent、QAAgent StateGraphs）。
- 代理注册表，用于集中式 intent→agent 分发。
- 通过 LangGraph MemorySaver 的多轮对话记忆（进程内内存，可升级到 SqliteSaver）。
- mock LLM 行为并使用隔离测试数据库设置的测试 fixtures。

## 延迟工作

README 和 MVP 规范将以下内容列为未来范围：
- 群机器人 webhook 推送公告、摘要和通知（WechatWebhookClient 已存在，需要调度器 + 代理集成）。
- APScheduler 定时提醒和每日报表。
- 持久化对话记忆（SqliteSaver — MemorySaver 是当前的进程内占位符）。
- RAG 或知识库集成。
- 自建应用回调的异步客服消息回复（智能机器人回调已通过 `response_url` 实现主动回复；自建应用仍使用同步被动 XML 回复，有 5 秒超时限制）。

## 工作指导

- 将当前应用视为基于 LangGraph 的工作 MVP，而非空白脚手架。
- 在添加实际集成时保留调试端点，除非用户要求替换。
- 在功能开发前，阅读 `docs/agent/patterns.md` 和相关测试。
- 在更改范围或架构前，阅读 `docs/agent/decisions.md`。
- 新代理遵循模式: State → nodes → graph → 在 `registry.py` 中注册。
