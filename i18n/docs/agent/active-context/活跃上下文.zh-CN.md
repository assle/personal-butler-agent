# 主动语境

## 当前状态

MVP已完成并迁移至LangChain + LangGraph。该应用公开 `POST /api/debug/message`、`POST /api/wechat/callback`（自建应用）和 `POST /api/wechat/robot/callback`（智能机器人），通过规则优先意图路由器路由消息，分派到四个 LangGraph StateGraph 代理之一，并在 SQLite 中保留健身/组消息/用户偏好状态。

当前实施基线：
- FastAPI应用入口：`src.main:app`
- 调试路线：`src/router/debug.py` — 支持chat_type/chat_id进行群聊模拟
- 企业微信自建应用回调：`src/wechat/router.py` — GET URL 验证+POST消息接收，AES-256-CBC加密，CorpID验证，被动加密XML回复
- 企业微信智能机器人回调：`src/wechat/robot_router.py` — GET URL 验证（receiveid=""）+POST智能机器人专用JSON解析，通过`response_url` POST主动回复
- 意图路由：`src/intent/rules.py` 和 `src/intent/router.py`
- 代理：`FitnessAgent`、`SummaryAgent`（文字+群）、`MealAgent`、`QAAgent`
- 代理注册表：`src/agents/registry.py` — 7 个意图→代理映射
- LLM：`langchain_openai.ChatOpenAI` 指向 DeepSeek
- 持久性：`training_records`、`user_preferences`、`group_messages`
- 多轮内存：LangGraph `MemorySaver` 检查点（内存中，每个 user_id 线程）
- 验证基线：82 项测试通过 `DEEPSEEK_API_KEY=test uv run pytest -q`
- 配置：`WECHAT_ROBOT_TOKEN` + `WECHAT_ROBOT_ENCODING_AES_KEY` 用于智能机器人回调（以及现有的 `WECHAT_CORP_ID` + `WECHAT_TOKEN` + `WECHAT_ENCODING_AES_KEY` 用于自建应用）

## 实施了什么

- 调试 API 请求/响应模式（使用 chat_type/chat_id 进行组模拟）。
- 企业微信自建应用回调（AES-256-CBC加密、XML解析、被动加密XML回复）。
- 企业微信智能机器人API回调（receiveid=""解密、智能机器人JSON消息解析、`response_url` POST主动回复）。
- 已知意图关键字的规则优先分类。
- 通过 LangChain ChatOpenAI 兼容 DeepSeek/OpenAI 的 LLM 后备分类。
- 训练记录提取和持久化（FitnessAgent StateGraph）。
- 基于最近历史记录的训练计划生成（FitnessAgent StateGraph）。
- 结构化聊天摘要——私人聊天文本和群聊历史记录（带有条件路由的SummaryAgent StateGraph）。
- 群聊消息被动采集：所有群消息保存到DB，触发关键词（“汇总”/“摘要”/“成就”/“汇总”）发起汇总。
- 偏好意识膳食计划和问答（MealAgent、QAAgent StateGraphs）。
- 用于集中意图到代理调度的代理注册表。
- 通过 LangGraph MemorySaver 进行多轮对话记忆（内存中，每个 user_id 线程）。
- 模拟 LLM 行为并使用隔离测试数据库设置的测试装置。

## 延期工作

README 和 MVP 规范将这些列为未来范围：
- 群机器人Webhook推送公告、摘要和通知（WechatWebhookClient存在，需要调度程序+代理集成）。
- 用于计划提醒和每日报告的 APScheduler 作业。
- RAG 或知识库集成。
- 自建应用回调的异步客服消息回复（机器人回调已使用 `response_url` 主动回复；自建应用仍使用同步被动 XML 回复，超时限制为 5 秒）。

## 工作指导

- 将当前应用视为 LangGraph 的可用 MVP，而不是空白的脚手架。
- 在添加实际集成时保留调试端点，除非用户要求替换它。
- 在功能工作之前，请阅读 `docs/agent/patterns.md` 和相关测试。
- 在更改范围或架构之前，请阅读 `docs/agent/decisions.md`。
- 新代理遵循以下模式：状态→节点→图→在`registry.py`中注册。
