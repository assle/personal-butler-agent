# 故障排除

## 由于 `DEEPSEEK_API_KEY` 缺失，测试失败

症状：
- 导入 `src.config.settings` 会引发设置验证错误。

查看：
- 使用 `DEEPSEEK_API_KEY=test uv run pytest -q` 运行测试。

原因：
- 即使在测试模拟 LLM 行为时也需要 `Settings.deepseek_api_key`。

## 真正的LLM通话发生在测试期间

症状：
- 测试会进行网络调用、挂起或因提供程序错误而失败。

查看：
- 检查模拟 LLM 客户的测试装置。
- 确认被测试的路径接收模拟而不是在内部构建新的客户端。

修复模式：
- 通过构造函数或路由器工厂注入 LLM 客户端。
- 将直接 `LLMClient()` 构造集中在应用接线中。

## SQLite 表丢失

症状：
- 运行时或测试因缺少 `training_records` 或 `user_preferences` 而失败。

查看：
- 应用启动应在 `src/main.py` 中运行 FastAPI 生命周期。
- 测试应通过 `Base.metadata.create_all` 创建元数据。
- 确保导入模型模块，以便元数据了解所有表。

## LLM JSON解析失败

症状：
- 意图回退到 `unknown`，或者训练提取返回解析错误。

查看：
- 确认提示仅要求 JSON。
- 确认解析代码可以处理格式错误的 JSON，而无需提升到 API 层。

修复模式：
- 保持安全的后备行为。
- 在加强解析之前添加格式错误的 JSON 测试。

## API 返回 LLM 服务错误

原因：

查看：
- 验证 `.env` 值。

- 确认运行时环境的网络访问。

## 智能机器人群聊收到消息但不回复

症状：
- 服务器日志显示已成功解密、解析并生成回复的消息。
- `Robot reply posted: status=200, body={"errcode":40008,"errmsg":"invalid message type"}`。
- 机器人不会将回复发送到群聊。

查看：
- 确认消息类型是 `markdown`，而不是 `text`。智能机器人`response_url`仅支持`markdown`和`template_card`，不支持`text`，返回errcode 40008。
- 请参阅 `src/wechat/robot_router.py:_post_reply()` 了解正确的有效负载结构。

修复模式：
```python
# Wrong — text not supported by robot response_url
payload = {"msgtype": "text", "text": {"content": content}}

# Correct — use markdown (or template_card)
payload = {"msgtype": "markdown", "markdown": {"content": content}}
```

## 智能机器人消息字段全部为空

症状：
- 解密后日志显示 `from_user=`、`chat_type=single`、`content=`，即使原始解密的 JSON 看起来是正确的。
- 消息被错误路由为私人聊天而不是群聊。

查看：
- 智能机器人使用与自建应用不同的 JSON 模式：
  - 机器人 JSON：`from.userid`、`text.content`、`chatid`、`chattype`、`response_url`
  - 自建应用：`from_user_name`、`content`、`chat_id`、`chat_type`
- 机器人回调（`src/wechat/robot_router.py`）必须解析嵌套的 JSON 键，而不是平面自建应用键。

## 智能机器人URL 验证失败，返回403

症状：
- GET URL 验证返回 403 以及正确的 Token 和 EncodingAESKey。

查看：
- 机器人使用 `receiveid=""`（空字符串）进行 echostr 解密，而不是 CorpID。
- 验证代码调用 `decrypt(encoding_aes_key, echostr, "")` — 使用非空 CorpID 会导致 `CorpIDMismatch`。
