# Troubleshooting

## 测试因 `DEEPSEEK_API_KEY` 缺失而失败

症状:
- 导入 `src.config.settings` 引发 settings 验证错误。

检查:
- 使用 `DEEPSEEK_API_KEY=test uv run pytest -q` 运行测试。

原因:
- 即使测试 mock 了 LLM 行为，`Settings.deepseek_api_key` 仍然是必需的。

## 测试期间发生真实 LLM 调用

症状:
- 测试发出网络请求、挂起或失败并返回提供商错误。

检查:
- 检查测试 fixture 是否有 mock LLM 客户端。
- 确认被测路径接收到的是 mock 而不是在内部构造新客户端。

修复模式:
- 通过构造函数或路由工厂注入 LLM 客户端。
- 将直接的 `LLMClient()` 构造集中在应用装配代码中。

## SQLite 表缺失

症状:
- 运行时或测试失败，提示 `training_records` 或 `user_preferences` 缺失。

检查:
- 应用启动应运行 `src/main.py` 中的 FastAPI lifespan。
- 测试应通过 `Base.metadata.create_all` 创建元数据。
- 确保模型模块已导入，以便元数据知道所有表。

## LLM JSON 解析失败

症状:
- Intent 回退到 `unknown`，或训练数据提取返回解析错误。

检查:
- 确认 prompts 只要求 JSON。
- 确认解析代码处理格式错误的 JSON 时不会抛出到 API 层。

修复模式:
- 保持安全的回退行为。
- 在收紧解析之前，先用格式错误的 JSON 编写测试。

## API 返回 LLM 服务错误

症状:
- 调试端点返回 `LLM 服务暂时不可用，请稍后重试。`

原因:
- `src/router/debug.py` 捕获了 agent 执行中的 `openai.APIError`。

检查:
- 验证 `.env` 值。
- 检查 DeepSeek base URL、model 和 key。
- 确认运行时环境的网络访问。

## 意外的 Intent

症状:
- 消息被路由到 Q&A 或 unknown，而非预期的领域。

检查:
- 搜索 `src/intent/rules.py` 查看关键字覆盖范围。
- 检查 `src/intent/router.py` 中的 `KNOWN_INTENTS`。
- 在更改路由行为之前添加或更新测试。

## 智能机器人收到消息但群聊中无回复

症状:
- 服务器日志显示消息已成功解密、解析并生成回复。
- `Robot reply posted: status=200, body={"errcode":40008,"errmsg":"invalid message type"}`。
- 机器人未在群聊中发送回复。

检查:
- 确认 msgtype 为 `markdown` 而非 `text`。智能机器人的 `response_url` 仅支持 `markdown` 和 `template_card` — `text` 不被支持，会返回 errcode 40008。
- 查看 `src/wechat/robot_router.py:_post_reply()` 中的正确 payload 结构。

修复模式:
```python
# 错误 — text 不被机器人 response_url 支持
payload = {"msgtype": "text", "text": {"content": content}}

# 正确 — 使用 markdown（或 template_card）
payload = {"msgtype": "markdown", "markdown": {"content": content}}
```

## 智能机器人消息字段全部为空

症状:
- 解密后日志显示 `from_user=`、`chat_type=single`、`content=`，即使原始解密 JSON 看起来正确。
- 消息被误路由为私聊而非群聊。

检查:
- 智能机器人使用与自建应用不同的 JSON 结构：
  - 机器人 JSON: `from.userid`、`text.content`、`chatid`、`chattype`、`response_url`
  - 自建应用: `from_user_name`、`content`、`chat_id`、`chat_type`
- 机器人回调（`src/wechat/robot_router.py`）必须解析嵌套 JSON 键，而非平铺的自建应用键。

## 智能机器人 URL 验证失败返回 403

症状:
- 即使 Token 和 EncodingAESKey 正确，GET URL 验证仍返回 403。

检查:
- 机器人使用 `receiveid=""`（空字符串）进行 echostr 解密，而非 CorpID。
- 验证代码调用 `decrypt(encoding_aes_key, echostr, "")` — 使用非空 CorpID 会导致 `CorpIDMismatch`。
