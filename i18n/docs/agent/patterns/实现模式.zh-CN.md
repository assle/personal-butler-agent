# 实施模式

## 应用装配

- `src/main.py` 在模块加载时构造单例服务对象：`LLMClient`、`IntentRouter`、每个代理和 `AgentRegistry`。
- FastAPI 生命周期通过 `Base.metadata.create_all` 创建数据库表，并在关闭时处置异步引擎。
- 路由模块在需要注入依赖项时应公开路由器工厂函数，遵循 `create_debug_router(...)`。

## 请求流程

1. API 路由接收 Pydantic 请求。
2. `IntentRouter.route(message)` 返回 `(intent, confidence)`。
3. `AgentRegistry.get(intent)` 解析已编译的图智能体。
4. 选定的代理构建初始状态并通过 `ainvoke()` 运行其图。
5. 结果包装在 `AgentResponse` 中并以 `DebugMessageResponse` 形式返回。

保持此流程线性，除非新功能明显需要编排。

## 意图路由

- 首先使用确定性关键字/规则匹配来获得稳定、常见的用户短语。
- 仅将 LLM 用作规则未分类的邮件的后备。
- 未知或格式错误的 LLM 分类输出应回落至 `unknown`，而不是抛出异常。
- 添加意图时添加规则命中和回退行为的测试。

## 图代理边界

每个代理都是一个 LangGraph `StateGraph`，包含三个文件：

```
agents/<domain>/
├── __init__.py   # Re-exports the agent class
├── state.py      # TypedDict state definition
├── nodes.py      # Single-responsibility async node functions
└── graph.py      # StateGraph assembly, agent class with handle()
```

- **状态**：定义流经图形的所有字段的 `TypedDict(total=False)`。默认情况下字段是可选的；节点仅更新其更改的内容。
- **节点**：异步函数 `(state: dict) -> dict` 返回部分状态更新。节点通过 `langgraph.config.get_config()` 访问运行时依赖项（LLM 客户端、DB 会话）。
- **图**：用`builder.add_node()`组装节点，设置入口点，定义边或条件边，并调用`builder.compile(checkpointer=...)`。
- **智能体类**：包装编译后的图。 `handle(intent, message, user_id, db)` 构建初始状态，将 `config` 与 `{"configurable": {"db", "llm", "thread_id"}}` 一起传递，并运行 `graph.ainvoke()`。

### 添加新代理

1. 使用 `state.py`、`nodes.py`、`graph.py`、`__init__.py` 创建 `src/agents/<domain>/`。
2. 定义状态 TypedDict。
3. 编写节点函数——每个函数只做一件事，返回部分状态。
4. 用节点和边组装图形。
5. 使用 `handle()` 实现智能体类。
6. 在`src/main.py`中注册：实例化并调用`agent_registry.register(intent, agent)`。

### 节点约定

- 调用 LLM 的节点：包装在 try/except 中，失败时设置 `error` 字段。
- 接触DB的节点：通过`get_config()["configurable"]["db"]`访问会话。
- 条件函数：同步函数 `(state: dict) -> str` 返回下一个节点名称。
- 保持节点集中——如果一个节点做两件事，则将其拆分。

## 数据库模式

- 仅使用 SQLAlchemy 异步 API。
- 将 `select(...)` 查询与配置中注入的 `AsyncSession` 结合使用。
- 当测试或响应数据需要在路由完成之前生成状态时，将 ORM 对象添加到会话和 `flush()` 中。
- 将可扩展用户首选项存储为命名空间键下的 JSON 文本，例如 `fitness` 和 `meal`。

## 测试模式

- 测试不应需要真正的 DeepSeek 调用。
- 使用 `conftest.py` 的 `mock_llm` 夹具（`AsyncMock()`）进行智能体测试 - 图形节点通过配置调用 `llm.chat()` / `llm.chat_json()`，并且模拟仍然拦截这些。
- 在fixture中使用内存中的 SQLite 或隔离的异步引擎。
- 添加行为时更喜欢集中模块测试和 API 冒烟测试。
- 图智能体通过 `handle()` 进行测试 - 与以前相同的接口，因此现有的测试模式仍然有效。
