# 升级路线图

记录当前项目中的可升级项目，按优先级排序。每个条目包括当前状态、目标状态和估计工作量。

---

## 1. 代理执行模式

### 1.1 内联 → 子代理驱动执行

- **当前**：使用`superpowers:executing-plans`在当前会话中顺序执行所有任务
- **目标**：使用`superpowers:subagent-driven-development`，将每个任务分派给独立的子代理并行执行
- **好处**：独立任务可以并行运行，减少总时间；每个子代理的上下文更清晰
- **工作量**：小（仅更改执行技能选择，无需更改代码）

### 1.2 标准化测试驱动开发

- **当前**：在实现过程中手动遵循TDD（先编写测试，然后实现），但不强制执行
- **目标**：每次实现前调用`superpowers:test-driven-development`技能，确保红绿重构循环
- **好处**：更严格的测试覆盖率，更少的回滚
- **努力**：小（流程改进）

---

## 2. 计划任务

### 2.1 APScheduler定时推送

- **当前**：已实现群机器人 Webhook 推送功能 (`src/wechat/webhook.py`)，但缺乏调度机制
- **目标**：集成APScheduler（`pyproject.toml`依赖中已有），实现每日训练计划推送、每周膳食报告等。
- **好处**：自动群组通知，无需手动触发
- **努力**：中（新的调度程序模块，定义工作职能，从生命周期开始）

### 2.2 定时提醒和摘要

- **当前**：无
- **目标**：APScheduler 驱动的个人提醒（补水、训练）和每日/每周报告摘要
- **努力**：中等

---

## 3. 企业微信能力提升

### 3.1 异步客服消息回复

- **当前**：智能机器人回调已经使用`response_url`（`src/wechat/robot_router.py`）主动回复，不受5秒限制。自建app回调（`src/wechat/router.py`）仍然使用同步被动XML回复； LLM 调用可能会超时
- **目标**：将自建应用回调也升级为异步回复，通过微信“客服消息”API或Webhook推送
- **好处**：解决自建app场景下LLM延迟超时问题
- **难度**：中（添加客服消息API客户端，重构自建应用 Router回复逻辑）
- **注意**：机器人回调已经是主动回复模式，可以作为参考实现

### 3.2 多消息类型支持

- **当前**：仅支持短信（图像/语音等回复“不支持”）
- **目标**：支持图像消息（训练记录的OCR识别）、语音消息（转录然后路由）
- **工作量**：大（需要 OCR/ASR 服务集成）

### 3.3 企业微信OAuth用户身份映射

- **当前**：使用 `FromUserName` (OpenID) 作为 `user_id`
- **目标**：通过企业微信OAuth获取真实用户信息，建立OpenID↔用户画像映射
- **好处**：用户身份更准确，跨会话用户数据关联
- **努力**：中等

---

## 4. 知识库和RAG

### 4.1 知识库整合

- **当前**：QA 代理完全依赖于 LLM 内置知识
- **目标**：整合矢量数据库（例如Chroma/PGVector），存储健身知识、饮食数据库、历史对话摘要，提高答案质量
- **好处**：更专业、个性化的答案，减少LLM幻觉
- **工作量**：大（选择向量数据库、设计嵌入管道、重构 QA 代理）

---

## 5. 工程基础设施

### 5.1 依赖管理标准化

- **当前**：`pytest` 和其他开发依赖项位于 `[project.optional-dependencies]` 中，不是由 `uv sync` 自动安装，每次都需要手动安装 `uv pip install`
- **目标**：迁移到 `[dependency-groups]` 或 `uv sync --dev` 兼容格式
- **努力**：小（修改`pyproject.toml`）

### 5.2 容器化部署

- **当前**：本地 `uv run uvicorn` 启动，无容器化
- **目标**：编写Dockerfile，支持`docker compose up`一键启动
- **好处**：部署一致性，更容易在企业微信回调所需的公网环境中部署
- **工作量**：小（单个 Dockerfile + compose.yml）

### 5.3 持续集成/持续交付

- **当前**：没有持续集成
- **目标**：GitHub Actions 自动化测试 + linting，在 PR 上自动运行
- **工作量**：小（单文件 `.github/workflows/test.yml`）

### 5.4 端到端测试

- **当前**：所有测试均模拟 LLM 和数据库
- **目标**：添加有限的端到端测试（真正的 SQLite + 真正的 DeepSeek 调用），在 CI 中手动触发
- **努力**：中等

---

## 6. 多用户和群聊

### 6.1 多用户群聊消息采集

- **当前**：已实现 - 组消息被动收集到 `GroupMessage` 表中，触发关键字检测调用 LLM 汇总。同时支持自建APP和智能机器人回调通道
- **目标**：增强的多组支持、跨组用户身份映射、每用户/时间段聚合摘要
- **努力**：中等
